> 用途：为 `dsh-ocr1-memory`（OCR1 光学长期记忆插件）建立**事实级**验收基线。

## 1. 溯源澄清（先定边界）

1. **2510.18234 是什么**：DeepSeek-AI（Wei/Sun/Li，2025-10-21）的**技术报告**，核心命题 = 用视觉通道做文本压缩（"compressing long contexts via optical 2D mapping"），模型 = DeepEncoder（~380M 编码器）+ DeepSeek3B-MoE-A570M（解码器）。它**不是记忆系统论文**，只把「记忆遗忘机制」列为**未来方向提案**（Discussion §5 + Figure 13）。
2. **插件里 SoM 编号 / locate-and-transcribe / active recall 的源头不是 2510.18234**：项目 `.workbuddy` 会话记录明确写"OCR-Memory 论文（ACL 2026，以 DeepSeek-OCR 3B 为 backbone 的记忆系统）"。这些是另一篇论文（2604.26622）的概念，经插件二次工程实现。2510.18234 本身没有 SoM、没有段定位、没有 read-back fetch 协议。
3. **官方仓库不含训练代码**：README + 仓库树（7 commits）= 推理脚本（vLLM run_*、HF run_dpsk_ocr）、config、requirements、paper、assets。无 collator/trainer/embeddings API/示教。DeepEncoder 训练代码在官方模型卡与 Unsloth 生态，非本仓库。

因此，本清单对 2510.18234 的「原生」判定只认论文+官方仓库；插件凡是借 OCR-Memory / 自研的机制，一律标"工程扩展」。

## 2. 七个核心构想的逐项判定

### 2.1 2D optical mapping（光学 2D 映射）
- **论文原生**：✔ 论文第一句就是"compressing long contexts via optical 2D mapping"；Intro 明确"rendering previous rounds of historical text onto images"（文本渲染成图像 → 视觉 token 承载文本信息）；§4.1 展望"future… nearly 10× lossless contexts compression through text-to-image approaches"。这是论文的**概念层面**机制，论文内部实现是"文本↔图像（合成数据）→编码器→视觉 token→解码器 OCR"。
- **插件对应**：文本段落 → Pillow 渲染成 SoM 编号图像 → 存图像而非纯文本 → OCR 读回。属于工程实现对论文概念的落地，且加了 SoM（来源于 OCR-Memory）。
- **验收标准（事实级）**：
  - A1 存储形态：`store` 后磁盘上必须存在渲染 PNG（而非只存 JSON），且 PNG 内容与源文本段一一对应（可抽查 hash/内容渲染比对）。
  - A2 检索路径：`retrieve` 在光学后端可用时必须发起图像读回（可日志/计数验证），后端不可用则降级文本路径且须明示降级。
  - A3 措辞基线：文档/注释允许称"光学 2D 映射思路落地"，不得称"复刻了论文的 2D mapping 管线"（论文管线 = 合成文本图像 + DeepEncoder，插件未复刻编码器）。
- **不可声称**：插件渲染质量、分辨率档位、token 数等于论文内部行为。

### 2.2 分辨率 / vision token 档位
- **论文原生**：✔ Table 1（Multi resolution support）给出**精确档位与 token 数**：
  - Tiny 512×512 → 64 tokens；Small 640×640 → 100；Base 1024×1024 → 256；Large 1280×1280 → 400
  - 动态分辨率：Gundam = n×640×640 + 1×1024×1024 → n×100+256；Gundam-master（续训） = n×1024×1024 + 1280×1280 → n×256+400
  - 有效 token 公式（Eq 1）：N_valid = ⌈N_actual × [1 − (max(w,h)−min(w,h))/max(w,h)]⌉（Base/Large 保长宽比 padding 后有效数小于名义数）
- **官方 README 佐证**：✔ Support-Modes 列出 Tiny/Small/Base/Large 四档 + Gundam 动态档（✅）。
- **插件对应**：`vivid → normal → fuzzy` 三级分辨率衰减，文档自述"tier 宽度参考官方 Large/Base/Small 分辨率模式"（docs/OPTICAL_MEMORY_WORKFLOW.md）。这是**档位思想的借用 + 自定衰减策略**，不是档位对齐。
- **验收标准（事实级）**：
  - B1 插件必须在配置/日志中记录每个 tier 的实际渲染宽高与后端上报的 vision token 数（marker-only prompt_tokens − 空基线，接口级测量），不得写死"64/100/256"除非渲染尺寸与该档官方尺寸一致且后端为官方 DeepSeek-OCR。
  - B2 断言档位对齐时，须同时给出：渲染尺寸、官方档位表、后端版本三要素，缺一不可。
  - B3 文档中"Large/Base/Small 模式参考"须写成"参考官方模式**命名/档位思想**"，不得暗示插件输出了 400/256/100 个与 DeepEncoder 等价的视觉 token。
- **不可声称**：插件 tier = DeepEncoder 分辨率模式；插件 token 统计 = 论文内部逐层输出。

### 2.3 OCR reconstruction（解码重建）
- **论文原生**：✔ 解码器公式（Eq 2）f_dec: ℝ^{n×d_latent} → ℝ^{N×d_text}，X̂ = f_dec(Z)，n ≤ N —— 解码器从压缩后视觉 latent Z 重建文本表示；解码器 = DeepSeek-3B-MoE-A570M（6/64 routed + 2 shared experts ≈570M 激活）。§3.3 题为"decoder reconstructs the original text representation"。
- **插件对应**：OCR 读回 = 通过 OpenAI 兼容 `/v1/chat/completions` 请求后端（llama.cpp GGUF / vLLM 官方）把渲染图像转回文本；fetch 阶段只从**持久化原文**取回选中段（确定性返回 verbatim），不把 OCR 结果当权威文本。这是对"解码/重建"的**接口级近似**：调用的是模型推理接口，不是论文内部 latent→text 张量链。
- **验收标准（事实级）**：
  - C1 往返一致性：store(段 S) → OCR 读回 → 与持久化原文比对；编辑距离阈值（如 <0.05）内才算读回成功，且**最终返回文本必须来自持久化原文**（可检测 fetch 是否读原文文件）。
  - C2 后端身份：日志记录 ocrModel（默认 deepseek-ai/DeepSeek-OCR 或 GGUF 变体），不得把任何模型输出含糊表述为"DeepEncoder 输出"。
  - C3 明确性是接口近似：文档须写"OCR 读回 ≠ DeepEncoder 内部解码"，若已写（OPTICAL_MEMORY_WORKFLOW.md:131 等）则保持。
- **不可声称**：读回文本 = f_dec(Z) 的等价输出；无官方模型时"重建精度 97%"（那是 Fox 基准测试指标，见 2.4）。

### 2.4 compression ratio 与精度曲线
- **论文原生**：✔ 压缩比定义 = 真实文本 token（GT 用模型 tokenizer 分词）/ 视觉 token 数（Table 2 表头："Text tokens represent the number of tokens after tokenizing the ground truth text…"）。实测曲线（Table 2 + 图 1a，Fox 基准，文档 600–1300 token）：
  - <10× → ~97% 精度（各区间 96.5%–98.5%，如 600–700t/64v=10.5×→96.5%；600–700t/100v=6.7×→98.5%）
  - 10–12× → ~90%；20× → ~60%
- **插件对应**：`ocr1_mem_metrics` 估算文本 token（calibrate：向后端发纯文本请求得 prompt_tokens 基线）/ 实测视觉 token（marker-only 差值）。属**指标近似**：估算方法、模型、语料都与论文不同，不能外推论文曲线。
- **验收标准（事实级）**：
  - D1 metrics 输出必须同时给出：估算文本 token、实测视觉 token、压缩比、**估算方法与后端身份**（calibrate 记录）。
  - D2 文档若引用"10×→97%"必须标注：该数值仅在论文 Fox 基准 + 对应 tokenizer + 特定 prompt（"<image>\nFree OCR."）下成立，插件未复测不得声称复现；复测须同口径（同 prompt、同分词方式、VT=64/100）。
  - D3 不得把「渲染尺寸小 = 压缩比高」当论文行为；压缩比在插件语境是**工程度量**（估算文本 vs 测量视觉），不是论文内部 latent 压缩率。
- **不可声称**：插件达到 / 复现论文 97%@10×、60%@20× 曲线，除非按 D2 同口径复测。

### 2.5 historical memory / forgetting（历史记忆与遗忘）
- **论文原生：提案级（proposed，未实现/未验证）** ⚠️ 关键区分：
  - Abstract 只提"considerable promise for…memory forgetting mechanisms in LLMs"；
  - Discussion §5 + Figure 13 明确是**设想**："render previous rounds of historical text onto images, then progressively resizing older images to achieve multi-level compression, token counts gradually decrease and text becomes increasingly blurred, thereby accomplishing textual forgetting"；"mirror biological forgetting curves"；
  - 论文自认早期："we acknowledge this is early-stage work"；§6 "OCR alone is insufficient to fully validate true context optical compression and we will conduct digital-optical text interleaved pretraining, needle-in-a-haystack testing, and other evaluations in the future"——**论文没有实现、没有遗忘曲线数据、没有 tier 定义**。
- **插件对应**：`vivid(≤1天) → normal → fuzzy(>7天)` 年龄衰减 + 命中低清记忆触发 active recall 恢复高清。这是把论文提案**首次工程实装**，时间边界/档位/回读流程全是插件自定（文档自述默认边界）。
- **验收标准（事实级）**：
  - E1 衰减确定性：同年龄/命中情况两次运行行为一致（tier 判定只依赖持久化时间戳 + 配置），可脚本复验。
  - E2 active recall：命中 fuzzy/normal 段时，必须触发高清重渲染并更新持久化（可用 mtime/版本字段验证），且不得丢失原文。
  - E3 措辞基线：应称"实现了 2510.18234 Discussion 提案的工程化版本"；**不得称论文已证明该机制有效**（论文无数据）。
  - E4 若未来做遗忘曲线实验，须明确是**插件自己的实验**，与论文无对照数据可引用。
- **不可声称**：论文支持了某一具体 tier 宽度/衰减率；"遗忘机制"是论文已验证能力。

### 2.6 grounding / locate
- **论文原生**：✔ 但含义是**图像/版面空间定位**，不是记忆定位：
  - Prompt 模板：`<|grounding|>Convert the document to markdown.`（版面级 OCR，坐标归一化 1000 bins，fine annotation 交错布局+文本，见 Fig 5）；`<image>\nLocate <|ref|>xxx<|/ref|> in the image.`（refer 目标在**图内**定位）；
  - §3.4.3：general vision 数据含 caption/detection/grounding（~20% 数据，保住通用视觉接口）。
- **插件对应**：`opticalLocator` = 让模型输出 K 位 0/1 标签选择记忆段（阈值 + Top-K）。这是**记忆段选择/溯源定位**，与论文"图内 grounding"不同义；更接近 OCR-Memory 的 locate-and-transcribe。插件另有 `memory_expand`（源 session/seq 溯源）。
- **验收标准（事实级）**：
  - F1 文档须区分两种"grounding"：论文 = 图内坐标/引用定位（模型能力）；插件 = 段选择/溯源（记忆层功能）。不得混写。
  - F2 locate 准确度验收：构造已知段集合，top-K 命中率与阈值关系可复测（阈值 0.4/TopK 5 是配置项，须有测试记录）。
  - F3 若插件向 OCR 后端传 grounding prompt 取版面信息，可注明"复用模型能力"，但不等于记忆定位被论文定义。
- **不可声称**："论文支持记忆 locate"；"插件 locate = 论文 grounding"。

### 2.7 embedding（视觉嵌入检索）
- **论文原生**：✖ 不存在检索式 embedding 概念。
  - 全文 "embedding" 仅出现在 3 处，全是**网络层名词**：Fig 3 架构图 "Embedding layer"，§3.2.1 "we remove the first patch embedding layer"（CLIP 输入不再是图 → 去掉 patch embedding 层），§3.5.2 "treat the CLIP part as input embedding layer"（PP1 中 CLIP 当输入嵌入层）。
  - 论文无 embeddings API、无向量检索、无 pooling/投影、无相似度召回。压缩表示 = 视觉 latent Z ∈ ℝ^{n×d_latent}（Eq 2），且是解码器输入，论文从未把它当检索向量用。
- **插件对应**：`/v1/embeddings` 可选视觉 embedding（llama.cpp 实测：直接视觉 token=784，dim=1280，mean pooling），`embeddingRetrieval` 默认 **false**（区分度未充分验证前不作主检索信号）——方向正确。
- **验收标准（事实级）**：
  - G1 措辞必须写"接口级视觉 embedding（后端 /v1/embeddings 返回）"，**不得写"DeepEncoder 内部表示"**（docs 已写："返回的向量不能直接证明等于论文内部的 DeepEncoder 表示…需要官方模型代码、处理器、pooling/projection 位置和逐项校准"——保持此纪律）。
  - G2 若要声称"与 DeepEncoder 等价 embedding"，验收门槛 = 同一输入下与官方模型卡内部 latent（含 pooling/projection 位置）逐项对比；做不到就维持"接口级"。
  - G3 embedding 失效策略（图像版本/内容变化 → 旧 embedding 判失效）须可验证（版本字段哈希变化触发重新度量）。
- **不可声称**：embedding 来自论文机制；embedding 检索是 2510.18234 支持的用法。

## 3. 「完整 DeepEncoder 复刻」红线（措辞与验收底线）

论文 DeepEncoder = **已训练模型组件**，结构：SAM-base（80M，window attention 主导）→ **16× 卷积压缩器**（2 层 conv，k=3/s=2/p=1，channel 256→1024，4096 token → 256 token @1024²输入）→ CLIP-large（300M，dense global attention）。**完整复刻**的定义域：相同结构 + 逐层内部 latent 可导出 + 与官方权重行为可比对 +（可选）可训练。

插件现状（官方仓库 + 文档共同确认）：
- 通过 llama.cpp/vLLM **公开 HTTP 接口**调用模型（chat/embeddings），无内部张量、无逐层 visual token、无 hook；
- `docs/IMPLEMENTATION.md:113` 明载"DeepEncoder 内部压缩：未复刻"；
- `docs/DEPLOYMENT.md:57` 明载"token 指标是接口级统计，不是论文内部测量"。

**因此**：
- 允许表述："DeepSeek-OCR 思路/机制驱动""DeepEncoder-inspired""接口级近似"。
- 禁止表述："DeepEncoder 复刻/等价/输出等价视觉 token"，除非满足 G2 级别校准 + 逐层导出。
- 验收门禁（写代码/文档/发布时自查）：出现"复刻/等价/重现论文 97%"字样即 FAIL，必须替换为"接口近似/工程度量/参考论文曲线（未复测）"。

## 4. 一句话结论表

| 构想 | 2510.18234 原生? | 论文内部形态 | 插件形态 | 验收要点 |
|---|---|---|---|---|
| 2D optical mapping | ✔ 概念原生 | 文本↔图 + 编码器压缩 | 文本段渲染 SoM 图 + OCR 读回 | 存储形态=PNG；检索走读回 |
| 分辨率/vision token 档位 | ✔ 设计原生（Table 1） | 64/100/256/400、Gundam n×100+256 | vivid/normal/fuzzy 三级衰减（自定边界） | 档位断言须附 尺寸+官方表+后端三要素 |
| OCR reconstruction | ✔ 机制原生（Eq 2） | f_dec latent→text（3B-MoE） | /v1/chat 读回 + fetch 原文 | verbatim 返回；读回≠内部解码 |
| compression ratio | ✔ 指标原生（Table 2） | GT 文本token/视觉token，<10×→97%，20×→60% | 估算文本/实测视觉 token（calibrate） | metrics 附方法+口径；未复测不得引用曲线 |
| historical memory/forgetting | ⚠️ 提案级（未实现无数据） | Figure 13 设想：多级降分辨率模拟遗忘 | 年龄衰减 + active recall（首次实装） | 确定性衰减；措辞="论文提案的工程化" |
| grounding/locate | ⚠️ 能力原生（含义=图内定位） | <|grounding|>、Locate <|ref|> | 段选择（K-bit 标签）+ 溯源 | 两种 grounding 不得混写 |
| embedding | ✖ 不在论文 | 仅"input/patch embedding layer"词汇 | /v1/embeddings 1280d，默认关闭 | 只称"接口级"；等价须逐项校准 |

## 5. 当前插件验收锚点（2026-08-30）

- 当前 `npm test` 在真实 CPU-only llama-server 在线时为 **88/88 通过**；没有真实后端时，8 个 live-backend 用例会跳过。
- 已验证的运行链是 `llama-server` OpenAI-compatible `/v1` 接口 → OCR/可选 embedding → SoM 原文 Fetch；这不是 DeepEncoder 内部 tensor 导出。
- 维护实现是工程侧约束：默认 `maintenanceBatchSize=8`，按 namespace single-flight，支持取消传播，插件卸载会等待所属任务；这些不属于 2510.18234 的原生机制。
- 视觉 embedding 当前为接口级 1280 维结果，`embeddingRetrieval` 默认关闭；当前 probe 的直接视觉 token 由 marker-only 与空文本 `prompt_tokens` 差值计算（`785−1=784`）。
